# As Partner - OfficeHub

社内ポータルの**入口（ハブ）**となる、新規プロジェクトです。
勤怠管理・工数管理・タスク管理・業績管理などの社内システムを、ひとつの画面から横断します。

---

## ⚠ 最重要方針(絶対に守ること)

このリポジトリは、**既存システムには一切手を入れない**ことを大前提としています。

- 既存の勤怠システムのコードは変更しない
- 既存の GitHub リポジトリには上書きしない
- 既存テーブル / 保存ロジック / Supabase 連携 / RLS ポリシーには触れない
- OfficeHub は **新規リポジトリ・新規プロジェクト** として独立して構築する
- 既存システムとは、まずは **URL リンクで繋ぐだけ**

> 目的は「既存システムを壊さずに、社内ポータルの入口を新しく作ること」です。

---

## 移植ロードマップ

最終ゴールは、勤怠・工数・タスク・業績・申請・マスタを **すべて OfficeHub 内で完結** できる状態にすることです。
ただし、**既存システムを直接書き換えるのは避け、OfficeHub 側に段階的に移植する**方針で進めます。

### フェーズ

| フェーズ | 内容 | 状態 |
| --- | --- | --- |
| **1. 既存システムへの外部リンク接続** | サイドバー / TOP から既存システムへ新タブ遷移できる状態にする | ✅ **完了 (現在ここ)** |
| **2. TOP 画面・ポータル UI 完成** | ホーム / 共通レイアウト / サイドバー / ログイン / タスク一覧 UI 等 | ✅ 完了 |
| **3. 勤怠管理を OfficeHub 内に移植** | サイドバー「勤怠管理」を外部リンクから OfficeHub 内ページに切り替え。既存システム側は変更しない | 🚧 **進行中** (Phase 3-1 完了) |
| **4. タスク管理を OfficeHub 内に移植** | タスク一覧・タスクボードを OfficeHub 内に新規実装 | 未着手 |
| **5. 工数管理を OfficeHub 内に移植** | 工数入力・集計を OfficeHub 内に新規実装 | 未着手 |
| **6. 業績管理を OfficeHub 内で構築** | 売上・案件・粗利等のダッシュボード | 未着手 |
| **7. 外部リンクを廃止** | すべての機能が OfficeHub 内で完結したら、外部リンクを削除して内部ルートに統一 | 未着手 |

### 進め方の原則

- **一気に全部移植しない**。1 機能ずつ、動作確認しながら切り替える
- **既存システムは段階移行中も生かす**。OfficeHub 側の移植が安定するまで併存
- 各フェーズで切り替えるのは「サイドバー / TOP のリンク先」だけ。既存システム本体には一切手を入れない
- 切替方法は `src/config/navigation.ts` の各メニュー定義を、`href` (外部) → `to` (内部) に変えるだけ
- 切替の前後は `git` ブランチで分離する（例: `phase-3/kintai-migration`）

## セットアップ

```bash
# 依存インストール
npm install

# .env を作成 (.env.example をコピー)
cp .env.example .env
# Supabase URL / anon key / 各既存システム URL を編集

# 開発サーバー起動
npm run dev
```

> `.env` を設定しなくても **デモモードで画面確認が可能**です。ログイン画面で表示名を入れるだけで入れます。

## Supabase との接続方針

- **新規プロジェクトを推奨**: OfficeHub 用の Supabase プロジェクトを別途作成すると、既存への影響を完全に遮断できる
- **既存と同じプロジェクトを使う場合**:
  - OfficeHub からは既存テーブルに対して **SELECT のみ**
  - 既存の RLS ポリシーは変更しない
  - SELECT 権限が不足する場合のみ、別ポリシーを追加検討 (既存ポリシーは置き換えない)

## GitHub への push

```bash
git init
git add .
git commit -m "chore: initialize OfficeHub portal (new repository)"
git branch -M main
# GitHub 上で aspartner-officehub リポジトリを新規作成してから:
git remote add origin git@github.com:<your-org>/aspartner-officehub.git
git push -u origin main
```

> **既存リポジトリには絶対に push しないこと**。
> 新規に `aspartner-officehub` リポジトリを作成して、そこへ push してください。
